# S2 文档 RAG 开发计划(S2-PLAN)

**版本**:v1.0(**已完成并收尾**;需求见 `documents/S2-PRD.md`,表结构唯一出处
`documents/DB-DESIGN.md` §3,逐节讨论档案在个人工作区 `md_files/S2-*.md`,**不入库**,本文自足)
**日期**:2026-08-25(Phase A–E 全部通过;每个 stage 的 ✅ 块就是它的自测证据)

## 0. 总原则

1. **质量地基先做**:S2 的成败在**切分质量**与**图表描述质量**,所以这两件事排在最前,
   全部以 CLI 形态跑在 `tmp/s2-dev/` 里,**输出必须经需求方人工过目认可**才算通过。
2. **沙箱先行**:Phase B 的代码与产物只落 `tmp/s2-dev/`(独立 uv 项目,**禁止 import `server/`**,
   LLM 直调 openai SDK,索引用 numpy 内存实现);Phase C 才迁入 `server/` / `web/`,
   迁入时遵守 `DOMAIN-DEV-GUIDE.md`(只落自己域的文件夹)。
3. **逐段闸门,三个停车点**:切分 dump 人眼过目 / 描述质量与成本汇报 / 集成门槛逐项打勾。
   停车点不过不进下一步。
4. **真语料真跑,而且语料必须多样**:2026-08-25 一次加两份新文档就揪出**四个解析 bug**
   —— 前两份素材永远碰不到它们。**语料多样性是解析质量的唯一体检手段**,不是可选项。
5. **参数只量不猜**:每个阈值都要有一张实测表;**量不出分离度的参数就不实现**
   (`DOC_RAG_MIN_SCORE` 正是如此)。

**阶段总览**(严格串行;Phase B 是重心):

```
Phase A  文档地基:S2-PRD + DB-DESIGN §3                  (A1–A2)
Phase B  沙箱质量核心:契约→解析→切分→描述→检索评测       (B1–B5)★ 本计划的重心
Phase C  后端正式化:共享层契约 + 服务 + API + chat 接入   (C1–C4)
Phase D  前端:上传 / 审核台 / 引用回显                    (D1–D3)
Phase E  运营层 + 冒烟收尾                                 (E1–E3)
```

### 0.2 定位:问答链路的最后一棒

```
用户提问 → ① retrieve_exact_qa 高分命中 → 原样返回(Verified)
         → ② retrieve_text2sql  executed / refused_out_of_template → 各自短路
         → ③ retrieve_doc_rag ◀── S2 在这里
              ├─ 有召回 → generate,每个结论挂 [n] 引用(**不标 Verified**)
              └─ 无召回 → 兜底话术,**不调生成模型**
```

这个定位带来三条硬约束,贯穿全计划:

1. **不需要短路语义** —— S2 后面没有别人,只有"生成 / 兜底"两条出口;
2. **兜底话术由 S2 说出口** —— 整条链路"我找不到依据"这句话没有别人来说,
   所以**无召回时绝不能再叫一次 LLM**,否则系统的最后一道防线变成幻觉入口;
3. **进到 S2 的都是难题**(前两条链路都答不了的)—— 评测集必须照这个分布来,
   不能拿"一句原文就能答"的简单题撑门面。

> ⚠ **与总 PRD §4.3 冲突**:总 PRD 写的是"多链路并行执行再融合",需求方确认的是**串行兜底**。
> 并行融合属于 **S4**(Agent 编排)的范围。此条已进 `documents/S2-PRD.md` §8 冲突清单。

**做什么**:MinerU 块字段**全都收** —— 三组 caption + 三组 footnote + `table_body` +
`img_path` + `bbox` + `page_idx`;块类型 `type: str` **不用 Literal**;
"MinerU 给了但我们没声明的字段"打 debug 留痕。

**自测**:`check_contract.py` 对**现场调 MinerU 拿到的真实产物**退出码 0(不用手造 json 骗自己)。

> ✅ **已完成(2026-08-24)**:15 个字段全覆盖。参考的 `schemas/exact_qa.py` 本身漏了
> `image_footnote`/`chart_footnote`,是反面教材而不是抄写对象。

### B2 解析 `parse_pdf.py`

**做什么**:调 MinerU 常驻服务,参数照抄 S1 的 `call_mineru`;产物是**结构化中间表示**
(块序列,每块带 `heading_path` / `page_idx` / `bbox`),不是裸 markdown;
图片 base64 落盘,按内容 sha256 命名。

- 🩸 **`heading_path` 不是 MinerU 给的**:它只给 `text_level`,标题路径要**自己用栈在遍历块序列时推导**;
- 块类型判断收敛到两个集合常量(内容 / 噪声),**集合外的类型按噪声丢但不抛异常** ——
  这个设计就是为了让语料缺口浮出来而不是打死整篇;
- 🩸 **丢块留痕两处**:step log warning + `documents.meta` 按类型计数。

**自测**:① 标题树/表格/页眉页脚与原件人工抽查对得上;② 手改产物塞一个陌生 `type` 重跑 ——
按噪声丢、有 warning、**不抛异常**;③ 丢块计数出现在 meta dump 里。

> ✅ **已完成(2026-08-24;2026-08-25 扩语料后修四个 bug)**:8 条断言全过。
> **扩语料揪出的四个 bug 全部是"前两份素材永远碰不到"的**:
> ① **`code` 块被整体丢掉** —— MinerU 有 `type=code`(正文在 `code_body`),不在内容集合里
> → 一份文档丢了 7 个块,内容是 JSON 报文、API 响应、文件路径,**恰恰是用户会拿去搜的字符串**;
> ② **代码块必须逐字保留**,不能进句子切分(走一遍切句再拼回,JSON 报文被压成一行);
> ③ **退化图表块**:`type=table` 但 `img_path=''` 且无 `table_body` —— 既没图也没 HTML,
> 留着会在正文里留一个死占位符,解析期丢弃并留痕;
> ④ **纯标题片**:目录深的文档产生一批 5–9 token 的"只有一行标题"切片(实测一份 17 片),
> 搜不到东西还在向量空间里挤成一团 → **不出片 + 标题文本顺延给下一节**
> (只留在下级 `heading_path` 里不够:`tsv` 只索引 `content`,那个短语会从关键词索引里消失)。
>
> 同批还修掉**句子边界正则的两个字符级 bug**(潜伏已久):中文分支误写成 ASCII 的 `[。!?;:]`
> 而它的 `\s*` 是零宽的 → 任何 ASCII 冒号后面都下刀,`http://127.0.0.1:8766/x.html`
> 被切成三段再用空格拼回,**URL 报废**;拼回时一律加空格会在中文句子里插空格。
> **两个都是靠"原文不许丢字"这条断言抓到的** —— 这条断言值回票价。

### B3 清洗与切分 `clean.py` + `chunk.py` ★ 质量地基

**做什么**

- clean:去页眉页脚用**MinerU 的噪声块标注**,不用 LLM;丢弃内容留痕(同 B2 两处);
- 🩸 **行内 LaTeX 归一化**(纯函数,不调 LLM):MinerU 的公式检测会把 `−20 °C to +50 °C`
  这类**普通文字**判成行内公式,输出 `$- 2 0 ~ ^ { \circ } \mathsf { C }$`。
  **它对排版忠实,但对检索有害**:`tsv` 把 `2`/`0` 切成两个词,搜 "-20" 命中不了。
  范围卡死两条:只处理 `text` 块里的行内 `$…$`;**独立 `equation` 块一字不动**。
  认不出的命令、含上下标/分式的**原样保留** —— 宁可不改,不能改坏;
- chunk:按标题层级递归切,叶子超长按 512/80 二次切;**图表块整块不切**(宁可超上限),
  且**与前后各一段正文合成一片**(孤立描述块语义太薄);
- 🩸 **标题文本要进本节第一片的 `content`** —— `tsv` 只索引 `content`,标题只写进
  `heading_path` 的话,标题里的词永远进不了关键词索引;
- 🩸 **二次切分要保留段落边界**(段首之间用空行还原,不能全用空格拼);
- 图表在正文里先放占位符 `{{FIGURE:images/<sha256>.jpg}}`,B4 再替换 ——
  这样 golden 快照只钉正文切分,**描述换词不会让快照红**。

**自测(五条)**:① 可视化 dump 人眼过,无腰斩句、表格完整;② golden 快照建立(只钉正文切分);
③ 机器断言:不以半句结尾 / `seq` 连续 / token 在区间;④ 同一 PDF 跑两次逐字一致;⑤ 丢弃有留痕。

**★停车点 1**:dump 交需求方人眼过目,确认前不进 B4。

> ✅ **已完成(2026-08-25)**:**40 条断言 + golden 快照**;停车点 1 已过(需求方看过 `review.html`)。

### B4 图表描述 `describe.py` ★ 唯一 LLM 步骤

**做什么**:只处理含图表的片;`image` 与 `chart` 同一条代码路径(`chart.content` 恒空,
MinerU pipeline 无 VLM),`table` 单独一条。输入 = **截图** + 原文 caption/footnote + 前后各一段正文,
表格另加 `table_body` HTML 并标注"OCR 可能错行漏行,**以图片为准**";
`json_schema` 结构化输出 `{description, truncated}`;信号量并发 4;**逐块幂等**(已有描述的块跳过);
失败不改 `parse_status`,错误写 `documents.meta.describe_error`。

🩸 **描述必须写成"三段式",顺序即优先级**(2026-08-25 重写,原"先说行列维度"已废弃):
① **主旨句**(1–2 句陈述句):这张图表回答什么问题;② **覆盖清单**:全部型号/标准号/地区/
方法名等**实体标识符**;③ **逐行数值**(一个字不减),表格的行列维度挪到最后。

**为什么是这个顺序** —— 同一段描述要喂四个消费者,它们要的东西冲突:向量召回要短而集中
(长串数值稀释向量)、`tsv` 要越多字面量越好(词袋不稀释)、**重排 cross-encoder 只看得到前
400 token**(BERT 家族 512 位置硬上限,抬不上去)、生成要准确数值。
**不是取舍问题,是排序问题**:判别信号排前面,枚举排后面,四方都满足。

**主旨句的防编造纪律**(它是唯一的新风险,焊死三条):① 用词只能来自章节标题 / caption /
footnote / 前后正文 / 列名这五个来源,**禁止使用模型的世界知识**;② 可以命名"量的种类"
(看到 `AUD` 说这是价格)—— 这是读单位不是编事实;③ 可以描述看得见的趋势,
但不许说趋势的意义或哪个更好。另:**必须是陈述句** —— 第一版模型把"回答什么问题"理解成
"写出问题",开头全变成 "Which ...?",引用面板里给用户看像问卷。

**自测**:① 图片描述可用、无编造;② 表格描述含关键数值,小表逐行;
③ **硬判据:Table 1(Darknet-53)的描述必须含 HTML 丢掉的 `Connected 1000` 与 `Softmax` 两行**
(证明"看图绕过 OCR 错误"成立);④ 真实成本表。

**★停车点 2**:样例描述 + 成本表汇报,确认前不碰正式代码库。

> ✅ **已完成(2026-08-25)**:四条验收全绿,**四份语料 26 张图表全部描述完**。
> 三段式改写的客观验证:套话开头 **6/7 → 0/7**;延保价格表的 `cost`/`price` 由 **0 次 → 各 1 次**、
> `warranty` **3 → 6 次**(此前那张表的描述里 "warranty" 一次都没有,能被召回全靠 B3
> 的"标题进 content"兜底);重排窗口内可见实体 **15/16 → 16/16**,且无标识符丢失。
>
> 🩸 **`DOC_RAG_TABLE_EXHAUSTIVE_ROWS` 从 15 上调到 40,是被打脸打出来的**:
> Darknet-53 那张表 18 行,刚过 15 就触发截断分支,而模型把"最重要的行"理解成"最前面的行" ——
> 丢掉的恰好是表尾 `Avgpool / Connected 1000 / Softmax`,**和 MinerU 的 HTML 丢的是同三行**,
> 等于 describe 白做。两处同时修:阈值提到 40(表格是纯文本,token 成本远低于图片),
> system prompt 里写死"significant 不等于 first M 行,首行、**末几行**、以及任何带独立数值/
> 名称/输出形状的行必须覆盖"。修完同一张表模型读出 **24 行**(残差块逐层展开),
> 比第一次的 18 行还细,而 HTML 只有 19 行。

### B5 检索评测 `index_mem.py` + `retrieve.py` + `eval_run.py` ★ 集成门槛

**做什么**:内存双索引 + 混合检索 + 评测集跑分。链路六段:

```
query → ①改写(本期不做)→ ②双路召回(向量 Top-30 ∥ 全文 Top-30)
      → ③RRF 融合(k=60)→ ④cross-encoder 重排取 Top-5
      → ⑤上下文扩展(命中块前后各 1 块)→ ⑥交给 generate,强制引用
```

- 向量腿用 numpy 内存余弦(**不碰 pgvector**);
- 🩸 **关键词腿必须用真 Postgres,不用纯 Python BM25**:`RRF 吃的是名次不是分数`,
  而 `ts_rank` 没有 IDF、BM25 有 —— 同一批候选两者排出的名次可以不同,
  沿用 BM25 等于**在一把尺子上调参、拿另一把尺子交付**。做法:在沙箱自己的 scratch 表上
  原样跑 `to_tsvector('simple', content)` + `ts_rank`,**不碰共享表、不跑 alembic**;
- 🩸 **关键词腿必须自己去停用词再 OR**(这条对生产同样成立):`plainto_tsquery` 是
  **AND 语义**,而 `simple` 分词器**不去停用词** —— 一句自然语言问题会变成
  `how & much & does & it & …`,**命中 0 条**;改成纯 OR 又命中 111/116(几乎全库),
  而 `ts_rank` 没有 IDF,`the` 与 `warranty` 对分数贡献一样大,排序照样废。
  解法:自己维护停用词表,过滤后逐词 `plainto_tsquery` 用 `||` 并起来;
- 🩸 **检索输出契约:命中块必须随身带齐元数据** —— `chunk_id / doc_id / 文档名 /
  page_idx / heading_path / seq / 分数 / meta.figures`。citation 落库发生在 generate,
  **不会回头查检索现场**,这一环丢了后面补不回来。

**评测集四类题**(照兜底定位设计,开放式与跨切片占大头):单切片可答 / **跨切片才可答**
(RAG 相对精准 QA 的存在理由)/ 同领域但文档里没有(困难负例)/ 越界。

**自测**:① 四类题召回/命中表格;② 定稿 chunk 参数;③ 量出重排收益(passthrough vs 重排);
④ 打印真实分数分布;⑤ 记录重排延迟。

**★停车点 3 = 集成门槛**:全链路 CLI 走通 + 质量认可 + 参数定稿,才允许动正式代码库。

### C4 chat 接入:生成与引用(M7 / M8)

**做什么**:S1 零改写、S3 填模板,**S2 是唯一真靠 LLM 概括的域**,所以生成侧这几件事只能 S2 自己定

1. **prompt 形态**:每片一块,块头带 `[n]` 与 `heading_path`,正文原样;指令三句
   (只用给定材料 / 每个结论挂 `[n]` / 材料不足就说找不到依据);
2. **上下文预算靠条数**(`DOC_RAG_RERANK_TOPN=5`),不靠 token 动态截断
   —— 超长片在切分阶段就该被管住;
3. 🩸 **引用编号在后端拼 prompt 时定死**,一次写进 prompt 的 `[n]` 与 `message_citations.seq`
   两个地方。**不让 LLM 编号,也不事后解析答案反推** —— 这是 RAG 最经典的错位点,单测钉住;
4. 🩸 **定编号 ≠ 定入选**(2026-08-25 补的规格缺口):**入选 = 答案正文里真正出现过的编号**。
   有 `[n]` → 只挂出现过的那几条;有哨兵句无 `[n]` → **零引用**;
   都没有 → **保底挂 Top-1 一条**(有实质内容却忘标编号时,显示"无出处"比挂一条最相关的更糟)。
   **编号不重排**(只引了 `[1]` `[3]` 就显示 `[1]` `[3]`,留空号)、越界编号丢掉 + warning;
5. **哨兵句**:prompt 里指定一句**固定英文**,要求"材料里没有答案时只回这一句"。
   于是判据是一次**字符串比对**,不是关键词猜测,也不多花一次 LLM 调用。
   它同时就是兜底话术本身 —— 演示时每次拒答的措辞完全一致;
6. **`DOC_RAG_VERIFY` 一致性后校验**(默认关):开了用 light 模型跑一次"答案每句是否有材料支撑"。
   照 S1 那道 hit gate 的教训,**判据里必须写清"什么不构成否决"**(简短、措辞朴素、
   少了用户没问的细节),否则它会否掉合法答案;
7. **引用回显**:点开 `[n]` 要给**切片全文 + 元数据**,`![](images/…)` 要渲染成真实截图。

**自测**:trace 面板五要素;三 stage 依次出现;`[n]` ≡ `citation.seq` 单测钉住;
含图表的引用专门验一次图片能显示;文档里没有的问题 → 兜底话术且**引用面板一条都不挂**。

> ✅ **已完成(2026-08-25)**:落点 `core/chat.py::{_doc_rag_context,_doc_rag_citations,_doc_rag_used}`
> + `services/document/verifier.py`;9 条断言在 `tests/test_doc_rag_citations.py`。

> 🩸 **一个自找的坑,记下来。** 最初为了让退休行让开 `UNIQUE (doc_id, seq)`,把它的 `seq`
> 编码成 `-seq-1`。**这套编码跨代不唯一** —— 同一个 seq 退休第二次会撞同一个负号槽。
> 第一次重跑没事,第二次重跑发布时直接 `UniqueViolationError`,而且那次发布把 job 打成了 `failed`。
> 正确做法是把约束改成表达真正的意图:**`UNIQUE (doc_id, seq) WHERE status='active'`**。
> 改完之后 `retired_seq` / `original_seq` / 前端的 seq 还原逻辑**全部删掉** ——
> 少了一整套发明出来的机制,顺带还关掉一个潜伏缺陷(旧写法重新发布只删 `active` 行,
> 用户手动禁用过的旧行会永远留下,既看不见也召不回)。
> > 教训一句话:**别为了绕开一个约束去发明编码,先问这个约束写得对不对。**
>
> **由此定下的退休规则**(已写进 DB-DESIGN §3):重新发布时,被引用过的旧行退休
> (`disabled` + 清向量 + `meta.retired=true`,**`seq` 原样保留**),
> **其余旧行(含用户手动禁用的)一律删除**。判据是 `meta.retired` 而不是 `status` ——
> `disabled` 有两个来源:人手点的「禁用」(可逆)与重新发布时的退休(不可逆),前端要能分开显示。

### E2 单文档重跑 + 检索调试台

**做什么**

**做什么**:照 `make smoke-s1` / `smoke-s3` 的套路,把 E1/E2 的四条断言落成脚本。

**自测(四条断言)**:① 禁用 → **两条腿都不再返回它**;② 启用 → 向量重建,又能被召回;
③ 禁用**被引用过**的切片 → 正式行仍在、历史引用仍可读;④ 单文档重跑 → 旧片退休而非物理删。

> ✅ **已完成(2026-08-25)**:`server/scripts/smoke_s2_api.sh`(12 步)挂在 `make smoke-s2`,
> 第四条另挂 `make smoke-s2-rerun`。**四条断言写得比本节要求更严:**
> - 断言 ① 除了"结果里没有它",还**逐条核对两条腿的召回条数各少 1** ——
>   只验前者会漏掉"只改了一条 SQL"这种情形;
> - 断言 ② **重排分必须与禁用前逐字相同**,钉住 `embed_input()` 只有一处;
> - 断言 ③ 另带两条错误路径(`chunk_already_disabled` / `chunk_retired`)。
>
> **三条设计取舍:**
> 1. **默认不留痕**(照 `smoke_s3_api.sh` 的纪律):禁用过的切片会启用回来,而且挂了 `trap` ——
>    半路失败也放回去。**留下一条搜不到的切片,比脚本失败本身更糟**;
> 2. **探针词取自语料自身**:拿最长那条切片 `heading_path` 的末段当查询词。标题文本一定
>    逐字在正文里(B3 把标题留在该节第一片),所以两条腿都必中 ——
>    脚本因此**不依赖任何硬编码的业务词**,换一份语料照样能跑;
> 3. **第四条单独一个 target**:重跑不可逆(重新描述花钱、切片 id 全换、旧行退休),
>    演示前不能跑。`make smoke-s2` 默认跳过并打印一行提示。
>
> **已验证它真的会红**:故意只摘掉全文腿那一份 `status='active'`(最典型的漏改),
> 脚本在断言 ① 当场失败并打出"两条召回 SQL 至少漏了一条",退出码 1。
> **一个从不失败的冒烟脚本没有价值**,所以这条验证本身也记在这里。

| `DOC_RAG_MIN_SCORE` | **不实现** | 见下 |

**为什么 `DOC_RAG_MIN_SCORE` 不实现(两条独立理由,都是量出来的)**

1. **量纲取决于最终用哪把尺子**:RRF 融合分天生在 0.03 量级(`Σ 1/(60+名次)`)、
   cross-encoder 是 logits(−10~+10)、余弦是 0–1。在量纲没定死之前填任何值都是埋坑
   (填 0.5 配 RRF = 全部结果被丢光,而且很难查);
2. **正负两堆严重重叠,阈值切不开**。S1 的结论在 S2 完全复现:**阈值只切得开"越界问题",
   切不开"同领域但没答案"**。最难的那道负例("某型号的延保价格")拿到的分数高于半数正例 ——
   因为那个型号确实在保修表里、延保价格表也确实存在,**只是这两件事没有交集**。
   这种题只能靠**强制引用 + 一致性后校验**,不能靠分数。

**本期的行为**:重排后取 Top-5 **不做分数过滤**;"无召回"只指**双路一条都没有**这一种情况。

**`guard` 与 `MIN_SCORE` 的风险量级不同**(这是 `guard` 敢上、`MIN_SCORE` 不敢上的原因):
后者定错会把结果**丢光**;前者最坏只是退回 RRF 名次,**下行有界**。
